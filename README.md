# PAMGuard Enterprise Port

A C++ engine and web service that reproduces selected [PAMGuard](https://www.pamguard.org/) passive-acoustic-monitoring maths — FFT/spectrogram, click detection, click train tracking (MHT), whistle/moan detection, multi-channel bearing localisation, noise band/LTSA monitoring, all three Ishmael detectors, and the matched-template click classifier — behind an HTTP API, with parity against the PAMGuard Java source proven by golden fixtures generated from PAMGuard's own classes. The normal operator surface now uses **one active controlled-unit project**: its PAMGuard-style Data Model owns module settings, typed source bindings, the generated runtime graph, display tabs, display instances, and saved layout.

The Java PAMGuard source in `PAMGuard_Java/` (version **2.02.18e**, commit `dca55c81ef6f1498a8a3b926c69e7182afb915ee`) is the reference oracle. The machine-readable pin is `reference-tools/pamguard-oracle.json`; see [docs/225](docs/225-java-oracle-pinning.md) for the evidence and transition boundary. This is not a loose rewrite: every ported algorithm is either pinned to fixtures generated by running the *real* PAMGuard classes, or its divergence is documented explicitly. Correctness comes before convenience, and honesty about gaps comes before feature claims.

**Current state: 163/163 CTest checks · one ETag-guarded controlled-unit project authority · PAMGuard-style Data Model operator shell · project-native Acquisition, displays, audio, recorder, clips, and tracked-click target motion · Java-pinned scientific fixtures · legacy sessions/jobs isolated behind explicit compatibility mode.**

## What exists

| Component | Description |
| --- | --- |
| **C++ engine** (`cpp-engine/`) | Static library of ported PAMGuard maths: windowing, real FFT, spectrogram; click trigger/features, Basic and Sweep classifiers, angle vetoes; click train tracking (simple ICI tracker *and* the full ported MHT stack); Whistles & Moans connected-region tracking plus optional legacy whistle peaks; correlation delays, pair/LSQ/ML-grid bearing localisers, and array/world geometry. |
| **Noise monitoring** | Octave-family filter-bank levels (`noiseBandMonitor`) and separate FFT interval statistics (`noiseMonitor`: mean, median, 95% bounds, min/max), calibrated to dB re 1 µPa. Long-term spectral average (`ltsa`), all three Ishmael detectors, and matched-template click classification are also served. |
| **HTTP service** (`pamguard_engine_service`) | Versioned `/v1/projects` and controlled-unit APIs own normal configuration, revisions, ETags, persistence, runtime projection, stable Acquisition/recorder/tracked-event operations, and data-block streaming. API-key auth and auditing remain available. Fixed sessions, session archive/jobs, legacy capture identities, Workspace state, and low-level Acquisition ingress require explicit compatibility mode. |
| **Web UI** (`web-ui/`) | The normal root is a PAMGuard-style Data Model shell, not a dashboard of fixed detector pages. It builds menus/providers from the controlled-unit catalogue, renders actual project bindings as graph lines, applies settings with OK/Cancel to the stopped working project, owns display instances under controlled units, exposes Start/Stop, and surfaces stale-client conflicts without retrying them. A named legacy oracle harness remains local/test-only and is excluded from the production container. |
| **Project data streams** | Typed data-block history and NDJSON/audio streams drive the configured Spectrogram, Click, Level Meter, and Sound Output clients. Slow presentation subscribers use bounded drop-oldest queues and do not become a second scientific-processing authority. |
| **Session archive & replay** | Compatibility-only result/audio archives and deterministic session replay remain for regression/import work. They are not graph-native project storage and create no Archive tab in the normal shell. |
| **Offline jobs** | Compatibility-only `/jobs` still analyses WAV or archived audio through fixed `AnalysisSession` machinery. It is disabled in normal mode until project-graph offline execution and an owning storage/query controlled unit exist. |
| **Ingest** | Project-authoritative multi-source supervisor: direct shell-free FFmpeg workers post PCM to stable Sound Acquisition unit IDs with active-project/revision/audio-shape checks and durable cursors. The old `ffmpeg_stream_ingest` session bridge is compatibility-only. |
| **Live capture** | Opt-in (`PAMGUARD_CAPTURE_ENABLED=1`): stable `/v1/projects/active/acquisitions/{unitId}/...` routes own revision-keyed host binding, status, and start/stop for each Sound Acquisition instance; host-specific device/URL/process state remains outside the portable project. The same stable instance identity is used by supervised external ingest. |
| **Project import** | `PamguardProjectConverter` currently converts a real PAMGuard `.psfx` into the retained compatibility-session JSON. Conversion into the new controlled-unit project document is not yet claimed. |
| **Reference tooling** (`reference-tools/`) | 61 Java fixture-family generators that drive real PAMGuard classes and emit the CSV fixtures the C++ parity tests replay; PowerShell generators for each. |
| **Ops & deploy** | Archive retention and event-index rebuild utilities (`ops/`), Dockerfile + compose file, starter Kubernetes manifests (`deploy/kubernetes/`), Windows GitHub Actions workflow. |

## What works, and how well

Four claim statuses are tracked per module in the
**[parity ledger](docs/126-pamguard-parity-ledger.md)** (the authoritative table
— read it before relying on any specific module):

- **Fixture parity** — validated against CSVs generated by running the real PAMGuard Java classes, typically to 1e-12 or better (several are exact or ~1e-17): windows, FFT, spectrogram chunking, click trigger/classifier, IDI statistics, all MHT chi2 variables, MHT kernel and full StandardMHTChi2 stack, spectrum templates, whistle contour delays, pair/LSQ/ML-grid bearing localisers, array shape semantics, streamer orientation, world and earth-frame vectors.
- **Foundation** — implemented with focused regression tests but not yet full PAMGuard equivalence: click train tracker end-to-end, whistle localisation service path, far-field bearings, train summaries.
- **Operational** — project/service/deployment features that are not detector
  maths: project authority, display/audio streaming, capture, recording,
  supervised ingest, and lifecycle.
- **Experimental/unavailable** — a controlled-unit contract exists but missing
  Java behaviour is explicit; it is not a module-equivalence claim. Session
  archive/jobs and multi-session benchmarks are compatibility evidence.

Deliberately preserved PAMGuard quirks (tests pin them so they can't silently "get fixed"): the frequency-overlap `max`-instead-of-`min` in whistle grouping, the time-delay chi2 drop-worst-pair rule, the theta grid that never reaches +π, `Math.toRadians`' one-ulp constant, and others — each documented in its slice doc.

## What is *not* done

Honesty section. These are recorded decisions or genuinely blocked items, not oversights:

1. **Deliberate non-ports (with evidence):** `SimplexBearingLocaliser`,
   `CombinedBearingLocaliser`, and `MLGridBearingLocaliser` v1 have zero live
   call sites in the PAMGuard tree ([docs/200](docs/200-remaining-bearing-localisers-non-port.md)).
   The deprecated legacy `DetectionGroupLocaliser` remains a separate non-port
   ([docs/192](docs/192-group-localiser-non-port.md)); this is distinct from
   the ported `DetectionGroupLocaliser2`/Least Squares path used by tracked
   click events.
2. **Documented substitution:** grid-selected (plane/volume) sub-arrays report `bearingLocaliser: "grid"` and the ported ML grid localiser runs, but `MLLineBearingLocaliser2` is only available as an unselected config flag because PAMGuard gates it behind an SMRU licence ([docs/199](docs/199-ml-line-bearing-variant.md)).
3. **Blocked on external data** (the complete list, [docs/204](docs/204-per-chunk-attitude.md)):
   - `.psfx` import from a **different** PAMGuard build — the converter is pinned and revalidated against `2.02.18e`; Java serialisation is version-brittle, and testing another version needs a file written by it.
   - Time-varying array **geometry** (towed-array deformation), **geographic position** (`LatLong`), and sub-chunk attitude interpolation — all need a live GPS/attitude feed. Static geometry, static + per-chunk attitude, and earth-frame vectors are done.
4. **Scale:** throughput is measured — 50 detector-loaded live sessions sustain **23–27× realtime** unarchived ([docs/207](docs/207-throughput-benchmark.md)), **12.0× with full result + audio archiving** (~13 MB/s written), and **11.6×** with the noise/LTSA/Ishmael monitoring modules added on top ([docs/221](docs/221-archive-throughput-benchmark.md)), all on one workstation via `service-throughput-bench.ps1`. The composable graph additionally passed an exact two-hour seven-node soak with four simultaneous fast/slow FFT, click-event, and audio clients ([docs/244](docs/244-operator-support-and-hardening-evidence.md)).
5. Tracked-click Least Squares now produces two-dimensional target-motion
   positions from explicit local navigation/pose samples. It is not a
   georeferenced GPS pipeline or a general 3D/simplex/MCMC localiser.
6. **Security:** a structured self-review is on record with fixes applied and accepted risks stated ([docs/212](docs/212-security-review.md)) — an *independent* review before internet-facing deployment remains the right call. TLS terminates at your ingress, not in the service.

## Installation

### Prerequisites (Windows; Linux via the Dockerfile)

| Tool | Used for | Notes |
| --- | --- | --- |
| Visual Studio 2022 Build Tools (MSVC, C++20) | building the engine | `vcvars64.bat` must be on a known path |
| CMake ≥ 3.20 + Ninja or VS generator | build system | |
| JDK 21 (Temurin tested) | reference tools: fixture generation, project import | only needed to *regenerate* fixtures or import `.psfx`; checked-in fixtures build/test without it |
| Maven (or `reference-tools/scripts/mvn-local.ps1`) | compiling the parent PAMGuard Java source to `target/classes` | same caveat — only for reference tooling |
| Python 3 | ops utilities, one generated header check | |
| FFmpeg | live-stream ingest bridge | only for ingest |

The Java reference is a separate checkout at `PAMGuard_Java/`. `reference-tools/scripts/mvn-local.ps1` verifies its exact pinned commit before invoking Maven and uses `PAMGuard_Java/target/classes` for reference work.

### Build and test

```powershell
# From a VS 2022 x64 developer prompt (or after calling vcvars64.bat):
cd cpp-engine
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure   # see the final CTest summary
```

`scripts/build-msvc.ps1` and `scripts/test-msvc.ps1` wrap the same steps. The
project-authority service smoke, project-shell browser smoke, legacy
compatibility smokes and scientific fixtures all run as part of CTest.

## Running the service

```powershell
# Minimal: port 8080, no auth, blank stopped project
.\build\Release\pamguard_engine_service.exe 8080

# Production-ish: one project authority, auth, recording, UI and capture
$env:PAMGUARD_API_KEY            = "change-me"          # or PAMGUARD_API_KEY_FILE
$env:PAMGUARD_PROJECT_DIR        = "C:\data\projects"   # engine-owned durable root
# Optional exact saved project to open on startup:
# $env:PAMGUARD_ACTIVE_PROJECT_ID = "00000000-0000-4000-8000-000000000000"
$env:PAMGUARD_RECORDING_ROOT     = "C:\data\recordings" # host Sound Recorder root
$env:PAMGUARD_WEB_UI_FILE        = "..\..\web-ui\index.html"
# Optional override; otherwise an existing assets directory beside index.html is used:
# $env:PAMGUARD_WEB_ASSET_DIR    = "..\..\web-ui\assets"
$env:PAMGUARD_OPENAPI_FILE       = "..\..\platform\openapi.yaml"
$env:PAMGUARD_CAPTURE_ENABLED    = "1"                # sound-card / stream capture API
.\build\Release\pamguard_engine_service.exe 8080
```

Normal-mode knobs include `PAMGUARD_MAX_PCM_BODY_BYTES`,
`PAMGUARD_HTTP_THREADS`, `PAMGUARD_CORS_ORIGIN`,
`PAMGUARD_AUDIT_LOG_FILE`, `PAMGUARD_INGEST_STATUS_FILE`,
`PAMGUARD_FFMPEG_PATH`, and `PAMGUARD_INGEST_EXE`. Session counts, session
archive/replay, and `/jobs` settings apply only when
`PAMGUARD_LEGACY_MODEL_COMPAT=1`.

`PAMGUARD_PROJECT_DIR` and its parent must be controlled by the engine service,
not a shared editor or an untrusted writer. Project files are locked,
fingerprinted and atomically replaced, but that directory ownership remains
part of the persistence contract.

`GET /assets/...` serves only allowlisted CSS, JavaScript, JSON/source-map,
image, font, and WebAssembly files from that canonical asset root. Traversal
and symlink escapes are rejected; arbitrary URL paths are never mapped to the
filesystem.

### Using the web console

Open **http://localhost:8080/** (with `PAMGUARD_WEB_UI_FILE` set). The normal
operator workflow has one configuration authority:

1. Use **File -> New project** or **Open project**. An empty project shows only
   the permanent **Data Model** tab and global Start/Stop controls.
2. Use **Add Modules** to create supported controlled units, or preview the
   Click monitoring template. Missing authoritative default providers can be
   added in the same project transaction. Experimental/unavailable types do
   not silently appear as completed PAMGuard modules.
3. Right-click a unit, use its cog, or select it from **Settings** to configure
   its real sections. Source selectors and graph lines edit the same typed
   binding. **OK** validates and changes the stopped working project
   immediately; **Cancel** changes nothing.
4. Add a User Display, then use **Display** to add a Spectrogram bound to a
   compatible FFT block. Its owned tab exists only while that controlled unit
   exists.
5. Use **Save** or **Save As** to persist controlled units, settings, sources,
   graph positions, display ownership and display layout together. A stale
   browser receives a visible conflict and its edit is not retried.

The old fixed Session, Module Graph and Workspace application is not loaded by
the normal root or shipped in the production container. A named local oracle
harness remains available only when the engine starts with
`PAMGUARD_LEGACY_MODEL_COMPAT=1`.

Acquisition host-device binding, continuous project-native capture, Sound
Output, multiple Spectrograms, Click Detector and its continuous Click display,
Sound Recorder, Clip Generator, and supervised external ingest use stable
project/controlled-unit identities. The retained session routes and
`ffmpeg_stream_ingest` bridge are compatibility/test interfaces, not a second
normal operator workflow.

### Legacy compatibility-session example

The normal browser does not call `/sessions/**`, and normal service mode returns
a compatibility-disabled response for it. Start a separate regression engine
with `$env:PAMGUARD_LEGACY_MODEL_COMPAT = "1"` before using the following
fixed-session oracle/import example:

```powershell
# 1. Create a two-channel session with click detection + localisation
$session = @'
{
  "sessionId": "demo", "sourceId": "demo-src",
  "sampleRateHz": 48000, "channelCount": 2,
  "fft": { "length": 512, "hop": 256, "windowType": "Hann", "channels": [0, 1] },
  "array": {
    "id": "demo-array", "speedOfSoundMps": 1500.0,
    "hydrophones": [
      { "channel": 0, "xM": 0.0, "yM": 0.0, "zM": 0.0 },
      { "channel": 1, "xM": 1.0, "yM": 0.0, "zM": 0.0 }
    ]
  },
  "click": { "enabled": true, "localisation": true, "thresholdDb": 10.0 }
}
'@
Invoke-RestMethod -Method Post -Uri http://localhost:8080/sessions -ContentType application/json -Body $session

# 2. Stream interleaved little-endian float32 PCM at it (repeat per chunk)
Invoke-RestMethod -Method Post `
  -Uri "http://localhost:8080/sessions/demo/pcm-f32le?startSample=0" `
  -ContentType application/octet-stream -InFile chunk.f32le
# The response is the full versioned result JSON for that chunk:
# clicks, clickLocalisations (delays, pair/LSQ/grid bearings, world vectors),
# clickTrains, whistle regions/delays/groups, schemaVersion, continuity info.

# 3. Optional per-chunk array attitude (holds until replaced):
#    ...pcm-f32le?startSample=N&headingDegrees=42&pitchDegrees=-7&rollDegrees=11

# 4. Flush, inspect, query the archive, delete
Invoke-RestMethod -Method Post   -Uri http://localhost:8080/sessions/demo/flush
Invoke-RestMethod -Method Get    -Uri "http://localhost:8080/sessions/demo/archive/detections?type=click&limit=10"
Invoke-RestMethod -Method Delete -Uri http://localhost:8080/sessions/demo
```

Full API surface: **[platform/openapi.yaml](platform/openapi.yaml)** (also served at `/openapi.yaml` when configured). Result fields are versioned — see **[docs/74-result-schema-version.md](docs/74-result-schema-version.md)** for the schema history. The web UI is served at `/` when `PAMGUARD_WEB_UI_FILE` is set.

## Importing a PAMGuard project (.psfx)

Runs on the JVM because `.psfx` payloads are Java-serialised object graphs ([why](docs/182-project-import-feasibility.md)):

```powershell
# Compile PAMGuard + reference tools first (once):
.\reference-tools\scripts\mvn-local.ps1 -DskipTests compile

# Convert a settings file to an engine session JSON:
java -cp "<build>;<target/classes>;<deps>" org.pamguard.port.reference.PamguardProjectConverter `
     convert MyProject.psfx session.json
# ...then POST session.json to /sessions (add ownerId/tenantId if enforced).
```

`reference-tools/scripts/generate-project-import-fixture.ps1` shows the exact classpath incantation, and the HTTP smoke round-trips the `2.02.18e`-generated sample end to end. Everything the engine supports is mapped; everything else is **reported and skipped, never silently dropped**. Java-serialised files are version-sensitive; the current oracle pin is recorded in [docs/225](docs/225-java-oracle-pinning.md), and the original converter work is described in [docs/203](docs/203-project-import-converter.md).

## Live ingest

The normal path targets Sound Acquisition instances in the active controlled-unit
project. Save/open the project, start its runtime, and read its stable target IDs
from `GET /v1/projects/active/acquisitions`.

```powershell
# Copy the schema-v2 example, replace projectId/acquisitionUnitId/source,
# enable the intended sources, then validate without launching FFmpeg:
python ops\ingest_supervisor.py `
  --config platform\ingest-sources.example.json `
  --validate

# Remove --validate to run the supervised source workers.
```

Each worker discovers and verifies the active project, Acquisition unit, audio
shape, runtime state, working revision, and absence of built-in capture before
launching FFmpeg. PCM is sent to the stable project Acquisition endpoint; no
AnalysisSession or hidden runtime-node ID is created. Persist the configured
cursor directory, and run only one worker per Acquisition timeline.

`ffmpeg_stream_ingest` and
`platform/ingest-sources.legacy-session-compat.example.json` remain explicitly
deprecated compatibility assets for old session-based regression/archive
workflows. See [docs/91](docs/91-ingest-supervisor.md).

## Regenerating parity fixtures

Fixtures are checked in; regenerate only when deliberately re-pinning against the Java oracle:

```powershell
.\reference-tools\scripts\mvn-local.ps1 -DskipTests compile
.\reference-tools\scripts\regenerate-java-fixtures.ps1  # complete corpus
.\reference-tools\scripts\generate-<name>-fixture.ps1   # one fixture family
```

Each generator compiles a small exporter that drives the *real* PAMGuard
classes. The corpus command also repeats project-fixture generation and rejects
nondeterministic Java serialisation. After regenerating, `git status` must show
no unexplained diffs to pinned fixtures.

## Development rules

- PAMGuard correctness/parity first; every change is an enterprise work package with its own doc.
- Behaviour or API output changes update the OpenAPI spec and bump the result schema version (asserted in three places by the smoke).
- New maths gets a fixture generated from the real Java classes wherever `PamController` coupling allows; where it doesn't, branch-coverage tests and an honest note in the ledger.
- Preserve reference quirks; pin them with tests so they cannot silently change.
- No destructive Git operations; commit small validated checkpoints.
